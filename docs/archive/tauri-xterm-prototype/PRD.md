## 1. 产品摘要

WinTerminal++ 是一款受 tmux 启发、以键盘操作为核心的 Windows 桌面终端复用器。用户可以直接从桌面、开始菜单或可执行文件启动应用，在一个应用窗口中创建多个标签页，并在任意标签页中向上、下、左、右分割终端窗格。

Rust 是终端进程、窗格布局、会话状态、配置和持久化的唯一权威状态源。Tauri WebView 负责界面渲染、终端画布和用户输入，不直接创建 Shell 进程，也不获得任意系统命令执行权限。

产品分两个会话阶段：

1. P0 桌面多窗格终端：终端进程由 Tauri Rust Core 管理，关闭应用会结束对应进程。
2. P1 持久会话：独立 Rust Session Daemon 管理终端进程，桌面 UI 可以分离、关闭并重新附加，形成真正接近 tmux 的会话体验。

## 2. 背景与问题

Windows 用户通常需要同时运行 PowerShell、CMD、WSL、开发服务器、日志命令和远程连接。现有操作经常依赖重复打开窗口、鼠标调整布局和手动寻找目标终端，主要问题包括：

- 窗口和标签数量增加后，终端上下文难以管理。
- 常见终端只支持有限方向的分屏，新窗格位置不够直观。
- 键盘移动、调整大小和关闭窗格缺乏统一操作模型。
- 应用窗口关闭或崩溃后，正在运行的长任务可能丢失。
- 不同 Shell 的启动目录、环境变量和快捷键配置不一致。

## 3. 产品目标

### 3.1 P0 目标

- 应用能够作为标准 Windows 桌面程序直接启动。
- 用户只使用键盘即可完成新建标签页、四向分屏、四向选中、缩放和关闭。
- 每个窗格拥有独立的终端进程、工作目录、滚动历史和运行状态。
- PowerShell、CMD 和 WSL 能在同一个标签页中并行运行。
- Rust 统一管理终端生命周期和布局状态，前端只负责展示与输入。
- 应用能够生成可安装包和可直接启动的 Windows 可执行程序。

### 3.2 P1 目标

- 关闭桌面 UI 后，用户可选择让终端进程继续运行。
- 用户可以命名、分离、列出和重新附加本机会话。
- UI 崩溃或重启后，可以重新获取布局快照和终端输出。
- 支持保存和复用工作区布局。

### 3.3 非目标

以下内容不属于 P0：

- 实现新的 Shell 语言或替代 PowerShell、Bash。
- 兼容 tmux 的内部协议、配置文件或插件 API。
- 多人实时协作终端。
- 通过公网直接暴露 Session Daemon。
- 移动端应用。
- 完整 IDE、文件管理器或代码编辑器。
- macOS 和 Linux 的首发适配。

## 4. 目标用户

### 4.1 主要用户

- 同时运行多个本地服务、测试和日志的开发者。
- 经常在 PowerShell、CMD 和 WSL 之间切换的 Windows 高级用户。
- 熟悉 tmux，希望在 Windows 桌面环境获得相似快捷操作的用户。
- 需要长时间运行构建、下载、爬虫或运维任务的用户。

### 4.2 高频场景

1. 启动 WinTerminal++，自动进入默认 PowerShell 窗格。
2. 在右侧创建 WSL 窗格，在下方创建日志窗格。
3. 使用方向键快捷操作在不规则窗格之间移动焦点。
4. 临时放大当前窗格查看输出，然后恢复原布局。
5. 创建新的标签页处理另一项任务。
6. 分离会话、关闭 UI，稍后重新打开并继续操作。

| 会话 Session | 一组可统一管理、保存或重新附加的标签页 |

| 窗格 Pane | 显示一个独立终端实例的最小区域 |

| 分离 Detach | 关闭 UI 连接但保留后台会话和终端进程 |

## 7. 功能需求

### 7.1 桌面应用与启动

#### FR-APP-001 直接启动

- 用户安装后可以从桌面快捷方式、开始菜单或 exe 文件启动应用。
- 开发环境通过统一脚本启动 Tauri 开发窗口。
- 首次启动自动创建一个默认会话、一个标签页和一个终端窗格。
- 启动过程不得要求用户先打开浏览器。

验收标准：

- 双击应用后出现独立桌面窗口。
- 前端资源由应用加载，不依赖外部网页服务。
- 默认窗格可以立即接收键盘输入并执行命令。

#### FR-APP-002 窗口状态

- 记忆上次窗口尺寸、位置和最大化状态。
- 支持最小化、最大化和全屏。
- P0 只要求一个应用窗口；多应用窗口进入 P2。
- 应用没有活动标签页时，自动创建默认标签页，不显示不可操作的空白窗口。

#### FR-APP-003 退出行为

- P0 退出应用时，明确提示即将结束仍存活的终端进程。
- 用户可以选择取消退出或确认终止。
- P1 启用 Daemon 后，退出选项调整为“分离会话”“终止会话”“取消”。
- 不允许 UI 已关闭但用户不知道后台是否仍有进程运行。

### 7.2 Shell Profile 与终端

#### FR-TERM-001 Profile

每个 Profile 至少包含：

- 唯一标识和显示名称。
- Shell 可执行文件路径。
- 参数数组，不接受前端拼接后的整段 Shell 命令。
- 默认启动目录。
- 环境变量增量。
- 图标、主题和光标样式。

内置 Profile：

- PowerShell。
- CMD。
- WSL；系统未安装时显示不可用状态而不是启动失败弹窗循环。

#### FR-TERM-002 终端生命周期

- Rust 创建、调整和终止 ConPTY 及其子进程。
- 每个窗格拥有独立 PTY、输入队列、输出缓冲和退出状态。
- 进程退出后窗格保留最后输出，并展示退出码和“重新启动”操作。
- Rust 错误必须转换为结构化错误返回前端，不允许因单个窗格失败导致整个应用退出。

#### FR-TERM-003 终端兼容性

- 支持 ANSI/VT 控制序列和 24 位颜色。
- 支持 UTF-8、中文宽字符、组合字符、Emoji 和 Windows IME。
- 支持复制、粘贴、文本选择、搜索和可配置滚动历史。
- 支持鼠标模式、Bracketed Paste 和应用键盘模式。
- 调整窗格尺寸后，Rust 必须向 ConPTY 发送正确的行列数。

#### FR-TERM-004 工作目录继承

- 新窗格默认继承当前窗格的工作目录和 Profile。
- 工作目录获取失败时退回当前 Profile 的默认目录。
- “继承工作目录”属于尽力保证能力；不同 Shell 必须通过适配器或 Shell Integration 逐步提高准确度。
- 失败时不得阻止创建窗格，并记录可诊断但不包含敏感信息的日志。

### 7.3 四向分屏

#### FR-PANE-001 创建窗格

用户可以在当前窗格的左、右、上、下四个方向创建新窗格。

| 命令 | 结果 |
|---|---|
| Split Left | 新窗格位于当前窗格左侧 |
| Split Right | 新窗格位于当前窗格右侧 |
| Split Up | 新窗格位于当前窗格上方 |
| Split Down | 新窗格位于当前窗格下方 |

默认规则：

- 分割比例为 50%。
- 创建成功后聚焦新窗格。
- 新窗格继承当前 Profile 和工作目录。
- 用户可以在创建前或创建后切换 Profile。
- 当前空间不足以满足两个窗格最小尺寸时拒绝分割并显示原因。

#### FR-PANE-002 布局模型

布局必须使用二叉分割树，叶子节点为 Pane，分支节点为 Split。

    Split Row, ratio 0.60
    ├── Pane A
    └── Split Column, ratio 0.50
        ├── Pane B
        └── Pane C

四向分割的状态变换：

- 向右：Row(Current, New)。
- 向左：Row(New, Current)。
- 向下：Column(Current, New)。
- 向上：Column(New, Current)。

布局不变量：

- 每个 Pane 在布局树中恰好出现一次。
- Split 必须始终拥有两个有效子节点。
- 关闭 Pane 后提升其兄弟节点，禁止留下空 Split。
- 分割比例必须限制在满足两侧最小尺寸的范围内。
- 活动 Pane 必须属于当前标签页。
- 每次布局变更必须原子完成并增加 revision。

### 7.4 四向焦点移动

#### FR-FOCUS-001 几何导航

- 用户可以从活动窗格向上、下、左、右移动焦点。
- 相邻窗格必须根据最终屏幕矩形计算，不能只按布局树兄弟关系选择。
- 候选窗格首先位于目标方向的半平面内，再按边缘距离、投影重叠和中心距离排序。
- 相同条件必须使用稳定 ID 作为最终排序依据，保证结果可预测。
- 默认到达边缘时不移动；循环跳转作为可配置选项。
- 焦点变更后，输入立即发送到新活动窗格。

验收标准：

- 在规则网格和三层以上的不规则嵌套布局中，方向移动均选择视觉上最合理的窗格。
- 不存在候选窗格时保持当前焦点。
- 关闭活动窗格后优先聚焦视觉距离最近的剩余窗格。

### 7.5 窗格尺寸与最大化

#### FR-RESIZE-001 四向缩放

- 用户可以向四个方向扩大或缩小活动窗格。
- 系统寻找目标方向上最近且轴向匹配的 Split 祖先并调整比例。
- 每次键盘操作使用可配置步长。
- 调整后所有受影响 PTY 必须收到新的行列数。
- P1 支持鼠标拖动分隔线。

#### FR-ZOOM-001 临时最大化

- 用户可以临时最大化活动窗格。
- 最大化只改变视图状态，不修改原始布局树。
- 再次执行相同命令恢复布局和原活动窗格。
- 最大化期间新建、关闭或移动窗格前必须先定义一致行为；P0 采用“自动退出最大化后执行命令”。

### 7.6 关闭窗格

#### FR-CLOSE-001 关闭规则

- 已退出进程的窗格可以直接关闭。
- P0 对仍存活的终端进程显示可配置确认；精确识别 Shell 内前台作业进入 P1。
- 关闭后自动提升兄弟节点并重新计算布局。
- 关闭标签页中的最后一个窗格等同于关闭标签页。
- 关闭最后一个标签页时自动创建默认标签页；只有显式退出应用才关闭桌面窗口。

### 7.7 标签页

#### FR-TAB-001 标签页生命周期

- 新建、关闭和重命名标签页。
- 切换到上一个、下一个或指定编号的标签页。
- 每个标签页拥有独立布局树和活动窗格。
- 标签标题默认来自用户名称、当前 Profile 或活动进程，按优先级选择。
- P1 支持拖动重排和保存标签页布局模板。

### 7.8 快捷键

#### FR-KEY-001 Prefix 模式

默认采用 tmux 风格 Prefix 键 Ctrl+B，避免全局快捷键直接占用 Shell 常用组合。

| 操作 | 默认快捷键 |
|---|---|
| 进入 Prefix 模式 | Ctrl+B |
| 向四个方向选择窗格 | Prefix，然后方向键 |
| 向四个方向创建窗格 | Prefix，然后 Shift+方向键 |
| 向四个方向调整窗格 | Prefix，然后 Ctrl+方向键 |
| 新建标签页 | Prefix，然后 C |
| 上一个/下一个标签页 | Prefix，然后 P / N |
| 跳转到标签页 | Prefix，然后 0-9 |
| 关闭活动窗格 | Prefix，然后 X |
| 最大化/恢复窗格 | Prefix，然后 Z |
| 重命名标签页 | Prefix，然后逗号 |
| 分离会话 | Prefix，然后 D；P1 |
| 取消 Prefix | Escape |

交互规则：

- Prefix 激活时展示轻量状态提示。
- Prefix 超时可配置，默认超时后取消且不执行命令。
- 快捷键必须完全可配置。
- 保存配置前检测重复绑定、不可达绑定和系统保留组合。
- 后续提供直接快捷键模式，但不得破坏默认 Prefix 模式。

### 7.9 状态栏与可见反馈

#### FR-UI-001 主界面

主界面由以下区域组成：

- 顶部标签栏。
- 中央窗格画布。
- 窗格标题或边框状态。
- 底部可选状态栏。
- 命令提示、错误提示和 Prefix 状态浮层。

#### FR-UI-002 窗格状态

每个窗格必须可区分以下状态：

- Starting。
- Running。
- Exited。
- Reconnecting；P1。
- Error。

活动窗格必须通过边框、标题色或状态标记清晰区分，不能只依赖非常轻微的颜色差。

### 7.10 配置

#### FR-CONFIG-001 配置存储

- 用户配置默认保存在 Windows 应用数据目录的 WinTerminal++/config.toml。
- Rust 负责读取、验证、迁移和原子写入配置。
- 前端不得直接获得任意文件系统读写权限。
- 配置错误时保留原文件，使用安全默认值启动并报告具体字段错误。
- 配置结构必须带 schema_version。

配置范围：

- 默认 Profile。
- Profile 列表。
- Prefix 和快捷键。
- 字体、字号、主题、光标。
- 滚动历史上限。
- 分屏比例、缩放步长和焦点边缘行为。
- 关闭确认和启动恢复策略。

### 7.11 会话与 Daemon

#### FR-SESSION-001 P0 会话

- P0 会话存在于 Tauri Rust Core 进程中。
- 可以保存配置和布局描述，但不能宣称保存了仍在运行的进程。
- 应用退出后再次打开，可以按保存的 Profile 和目录重新创建布局；这属于重建，不是重新附加。

#### FR-SESSION-002 P1 持久会话

P1 新增独立 Rust 进程 winterminald：

- Daemon 是 PTY、Shell 进程、会话、标签页、窗格和输出缓冲的权威状态源。
- Tauri Rust Core 通过仅限本机用户的 IPC 连接 Daemon。
- Windows 首选命名管道，并限制为当前用户访问。
- UI 附加时先接收带 revision 的完整快照，再接收有序增量事件。
- 每个终端输出块带 Pane ID 和单调递增序号，用于断线补发和重复过滤。
- UI 关闭不终止 Daemon；用户显式终止会话时才结束对应 PTY。
- 客户端和 Daemon 必须进行协议版本协商。
- Daemon 不监听公网端口。

P1 最低操作：

- 创建会话。
- 列出会话。
- 命名会话。
- 分离会话。
- 附加会话。
- 终止会话。
- 恢复布局、活动标签页、活动窗格和可用输出缓冲。

## 8. 技术架构约束

### 8.1 技术基线

| 层级 | 选择 | 职责 |
|---|---|---|
| 桌面框架 | Tauri v2 | Windows 生命周期、WebView、IPC、打包 |
| 核心 | Rust | PTY、进程、布局、会话、配置、安全边界 |
| 前端 | React + TypeScript + Vite | 界面、终端画布、用户交互 |
| 终端后端 | Windows ConPTY | PowerShell、CMD、WSL 的伪终端 |
| 终端渲染 | xterm-compatible renderer，技术验证后锁定 | VT 渲染、选择、滚动、输入 |
| P1 后台 | 独立 Rust Daemon | 持久会话和终端进程 |

前端框架仅用于表现层。以下逻辑必须位于 Rust：

- Shell 可执行文件和参数验证。
- PTY 创建、输入、输出、resize 和终止。
- Session、Tab、Pane 和 Layout 的权威状态。
- 配置读写与迁移。
- 关闭策略和进程生命周期。
- P1 Daemon 协议和本地 IPC。

### 8.4 Rust 模块边界

建议初始模块：

- app：应用启动与生命周期。
- commands：Tauri Command 注册和输入验证。
- terminal：PTY、Shell、输入输出与 resize。
- profile：Shell Profile 发现和解析。
- session：Session、Tab、Pane 状态机。
- layout：分割树、几何布局、焦点和缩放算法。
- keymap：命令定义与快捷键配置模型。
- settings：配置 schema、校验、迁移和持久化。
- transport：前端 Channel；P1 增加 Daemon IPC。
- diagnostics：结构化日志和错误代码。

### 8.5 前端模块边界

- app-shell：桌面应用框架。
- tabs：标签栏。
- panes：布局渲染和活动窗格状态。
- terminal-view：终端渲染器实例。
- command-dispatch：将用户意图映射到 Rust Command。
- settings：配置界面。
- overlays：Prefix、错误、关闭确认和命令面板。

前端不得维护一份可以独立修改的业务状态副本。前端可以缓存 Rust 快照，但所有变更必须通过命令提交，并以 Rust 返回的 revision 为准。

## 9. 状态模型

建议核心模型：

    AppState
    ├── sessions: Map<SessionId, Session>
    ├── active_session_id
    ├── profiles
    └── settings

    Session
    ├── id
    ├── name
    ├── tabs
    ├── active_tab_id
    └── revision

    Tab
    ├── id
    ├── title
    ├── root: LayoutNode
    └── active_pane_id

    LayoutNode
    ├── Pane(PaneId)
    └── Split(axis, ratio, first, second)

    Pane
    ├── id
    ├── terminal_id
    ├── profile_id
    ├── cwd
    ├── title
    └── process_state

所有 ID 在进程生命周期内不可复用。会话快照必须包含 schema_version 和 revision。

## 10. IPC 与事件规范

### 10.1 控制命令

低频控制操作使用已注册的 Tauri Commands，例如：

- create_pane。
- focus_pane。
- resize_pane。
- close_pane。
- zoom_pane。
- create_tab。
- activate_tab。
- update_settings。

每个命令：

- 接收结构化参数。
- 校验目标 ID 和当前状态。
- 返回新 revision 和必要状态增量。
- 返回统一错误对象，不向前端暴露 Rust panic 或系统敏感信息。

### 10.2 终端流

- 高频终端输出使用有序 Channel 或等价流式机制，不使用大量离散全局事件。
- 输入在前端短暂批处理后发送，不能为每个字节创建高成本调用。
- 输出流必须实现背压、批处理和有界缓冲。
- 窗格关闭后必须停止对应读写任务并释放订阅。

### 10.3 错误结构

错误至少包含：

- code：稳定机器码。
- message：用户可理解的消息。
- detail：可选诊断信息。
- retryable：是否可重试。
- pane_id 或 session_id：可选上下文。

## 11. 安全与隐私

### 11.1 权限边界

- Tauri capabilities 只授予主窗口所需的最小权限。
- 不给 WebView 开放通配符文件系统访问。
- 不开放通用 Shell 执行插件供前端任意调用。
- 所有进程启动必须经过 Rust Profile 校验。
- CSP 默认只允许本地资源；远程内容不得获得本地 IPC 能力。
- P1 命名管道只允许当前 Windows 用户访问。

### 11.2 数据保护

- 默认不采集遥测。
- 日志不得记录完整环境变量、命令中的令牌、剪贴板内容或终端完整输出。
- 崩溃报告必须由用户主动启用。
- 配置写入采用临时文件加原子替换，失败时保留上一版。

### 11.3 粘贴安全

- 支持 Bracketed Paste。
- 多行粘贴和包含控制字符的粘贴可配置确认。
- 前端展示的待粘贴内容不得自动执行。

## 12. 非功能需求

以下数值是开发目标，需要在参考设备上验证，不代表当前已经达到。

### 12.1 性能

- 冷启动至可输入状态目标不超过 2.5 秒。
- 本地输入到可见回显的 P95 目标不超过 50 毫秒。
- 窗格切换反馈目标不超过 100 毫秒。
- 8 个窗格连续输出 10 分钟时，界面仍可输入、切换和关闭。
- 单窗格默认滚动历史为 10,000 行，允许配置但设置硬上限。
- 输出消费速度不足时必须背压或有界丢弃历史，不允许内存无限增长。

### 12.2 稳定性

- 单个 Shell 启动失败不影响其他窗格。
- 单个终端渲染器异常不得破坏 Rust 会话状态。
- 所有后台任务都具有明确取消和资源释放路径。
- 不使用不可恢复的 panic 处理用户输入或 IPC 数据。
- 布局操作失败时保持原状态，不产生半完成变更。

### 12.3 兼容性

- 首发验证 Windows 10/11 x64。
- 首发 Shell 为 Windows PowerShell、PowerShell 和 WSL。
- 必须验证高 DPI、多显示器和系统缩放。
- 必须验证中文输入法、宽字符、Emoji 和中英文混排。
- Windows ARM64 进入后续兼容范围。

### 12.4 可访问性

- 所有核心功能均可通过键盘完成。
- 活动窗格不仅使用颜色区分。
- 提供可调整字号、对比度和光标样式。
- 状态错误保留可读文本，不只显示短暂 Toast。

## 17. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 将布局恢复误认为进程恢复 | 用户以为任务仍在运行 | 文案和架构明确区分 P0 重建与 P1 重新附加 |
| WebView 终端渲染性能不足 | 多窗格输出卡顿 | M0 做 8 窗格和中文验证，必要时更换渲染方案 |
| ConPTY 行为与不同 Shell 不一致 | cwd、resize 或按键异常 | Profile 适配层、Shell Integration、真实 Shell E2E |
| 高频输出淹没 Tauri IPC | 卡顿或内存增长 | Channel、批处理、背压和有界缓冲 |
| 快捷键与 Shell 或系统冲突 | 常用操作不可用 | Prefix 模式、冲突检查、完全可配置 |
| 前端获得过宽本地权限 | 命令执行和文件访问风险 | Rust 代理、最小 capabilities、禁止通用 Shell 权限 |
| Daemon 成为隐蔽后台进程 | 用户无法判断资源状态 | 明确托盘/会话列表、退出选项和终止入口 |
| 工作目录继承不准确 | 新窗格出现在错误目录 | 明确尽力保证，按 Shell 增加集成与回退 |
